# 决策力度与验证边界

目标是在可靠决策的前提下减少模型往返，不把“调用次数少”当成正确性的替代品。

| 力度 | 条件 | 执行者 | 当前证据 |
|---|---|---|---|
| 等待/机械动作 | 游戏仍在结算，或没有牌可打且无紧急药水选择 | 程序 | 多场实测 |
| 程序保命（guard） | 已知攻击可被一手牌完全挡下，且该牌无自伤/消耗/随机副作用 | 程序 | 离线测试；第39层实战触发 |
| 程序连续执行（resolve） | 本回合继续打“已知数值 + 已知目标”的攻击牌，且当前没有致命在即 | 程序 | 离线测试；第39层实战触发 |
| 连续计划 | 当前手牌和效果可预测，逐步结果与计划一致 | 程序；期间不问模型 | 精英与首领共3个双卡计划 |
| 常规局部选择 | 正常可行动状态，已识别意图，无直接致命风险 | Jev | 多敌、单敌、精英与首领实测 |
| 缩小选项重问 | Jev 低置信度，但程序能给出 2–3 个候选 | Jev（同一阈值） | 离线测试；阈值未下调 |
| 局部重排（同回合） | 新牌或局面微调，战术目标与生存约束不变 | 程序优先，必要时 Jev | 程序侧 resolve/guard 已实现；整回合自动重排仍未完整 |
| 回合重规划 | 新机制、攻防取舍、药水保命、原击杀目标失效 | 主模型 | 多场实测接管 |
| 长期策略 | 构筑、路线、休息、商店、关键事件 | 主模型 | 已覆盖相应实际流程 |
| 异常停机 | 旧状态、结果不明、预测偏离、接口错误 | 程序先停，再核实 | 离线异常测试；旧状态实测拒绝 |

## 连续打完的条件

只有整条序列的前提都成立，才能一次性打完整个回合。否则执行确定性前缀即可。预期中的扣能量、伤害和敌人死亡并不是新信息；抽新牌、随机目标/效果、意图变化、未预期的能力触发，才需要重新观察和安排。

程序自己出牌的三条硬边界（`src/policy.mjs`）：

1. **能杀就不用挡**：可斩杀全部存活敌人时直接执行斩杀线，不再考虑格挡。
2. **guard 从严**：只有在“已知攻击 → 一手牌完全挡下 → 该牌没有自伤、消耗、随机副作用”同时成立时才由程序出牌。带隐藏代价的牌（如消耗型格挡、随机消耗、失去生命）永远不进 guard。
3. **resolve 不赌命**：`resolve` 只打数值和目标都明确的攻击牌；未知效果（随机、生成卡牌、消耗、自伤）只有在本回合能直接击杀、或生命高于半数时才允许。

`plan` 不跨回合，不预测未知抽牌，不把一次HTTP成功或牌移出手牌当作结算完成。每步检查游戏队列、手牌、能量、血量、格挡、状态、敌人意图等；不吻合便停止。实际图像操作不是战斗循环的一部分。

## 下一轮优化的判断标准

1. 未知结果不能自动重复执行，计划偏离不能继续出后续牌。
2. 比较每回合模型往返数、完整回合耗时、主模型接管原因与实战损失。
3. 区分低置信度、真正危险、陌生规则和纯等动画。置信度不是正确率。
   主模型同样可能误算；实际出现过把现有10格挡加防御牌误判为无法挡15的解释。状态包提供程序计算的当前攻击总量和格挡缺口，帮助复核基本算术，但不冒充包含所有回合末效果的完整模拟器。
4. 优先消除“主模型重新确认原计划仍成立”这类无必要接管，而非直接降低置信度阈值。
   低置信度不再自动等于交回主模型：先看程序是否已有确定的 guard/斩杀线，其次用收窄选项重问 Jev；只有这些都拿不出可靠动作时才交回。
5. 不把胜利后的回顾伪装成行动前已知信息；对照应使用同一局面及相同规则。

当前低置信度阈值、低血量与药水阈值仍是保守试验规则，不是已经优化完成的通用策略。完整局结果及接管统计见 VALIDATION.md，回合级指标见 `scripts/metrics-jsonl.mjs`。
