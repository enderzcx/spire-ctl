# 决策力度与验证边界

目标是在可靠决策的前提下减少模型往返，不把“调用次数少”当成正确性的替代品。

| 力度 | 条件 | 执行者 | 当前证据 |
|---|---|---|---|
| 等待/机械动作 | 游戏仍在结算，或没有牌可打 | 程序 | 多场实测 |
| 程序保命（play） | 已知攻击会致死，且**恰好一种**出牌能完全挡下 | 程序 | 离线测试 + 实测 |
| 程序续打（resolve） | 能确认斩杀最后一只敌人 | 程序 | 离线测试 + 实测 |
| 策略续行（strategy） | 主模型已给带条件与失效条件的策略，且条件仍成立 | 程序 | **实测**：连续 12 步、0 模型调用、0 接管 |
| 机械推进（advance） | 免费领取、固定按钮、对话；战略选择一律停 | 程序 | 离线测试 + 实测（在事件处正确停下） |
| 短计划候选（candidates） | 有 2 个以上可核验前缀，逐张结算核对 | Jev | 离线测试 + 同一局面 A/B（请求数不变） |
| 连续计划 | 当前手牌和效果可预测，逐步结果与计划一致 | 程序；期间不问模型 | 精英与首领共3个双卡计划 |
| 常规局部选择 | 多张可打的牌、攻防取舍、能量分配 | Jev | 多敌、单敌、精英与首领实测 |
| 低置信度交回 | Jev 一次判断后仍不确定 | 主模型 | 离线回归：同一状态不再重问 |
| 局部重排（同回合） | 新牌或局面微调，战术目标与生存约束不变 | 程序优先，必要时 Jev | 程序侧 resolve/guard 已实现；整回合自动重排仍未完整 |
| 回合重规划 | 新机制、攻防取舍、药水保命、原击杀目标失效 | 主模型 | 多场实测接管 |
| 长期策略 | 构筑、路线、休息、商店、关键事件 | 主模型 | 已覆盖相应实际流程 |
| 异常停机 | 旧状态、结果不明、预测偏离、接口错误 | 程序先停，再核实 | 离线异常测试；旧状态实测拒绝 |

## 连续打完的条件

只有整条序列的前提都成立，才能一次性打完整个回合。否则执行确定性前缀即可。预期中的扣能量、伤害和敌人死亡并不是新信息；抽新牌、随机目标/效果、意图变化、未预期的能力触发，才需要重新观察和安排。

程序自己出牌的硬边界（`src/policy.mjs`）：

1. **能杀就不用挡**：可斩杀全部存活敌人时直接执行斩杀线，不再考虑格挡。
2. **保命要唯一**：只有“已知攻击会致死 + 恰好一种出牌能挡下”才由程序出牌；两种以上可行 → 交回 Jev（那本身就是取舍）。
3. **确认斩杀才续打**：只有“确认斩杀最后一只敌人”才由程序出牌。唯一一张可打牌仍与结束回合竞争，交给 Jev 或已批准的策略。自伤、消耗、随机、生成卡牌的文本一律不进程序判定。
4. **不做战术偏好**：程序不再“优先高伤害、否则防御/抽牌”。能算出伤害不等于能证明这张牌应该先出。

## 接管之后：策略续行

主模型评估风险后不必逐张牌接管。它可以把结论写成 `.runtime/strategy.json`（条件 + 失效条件 + 优先级），程序在条件成立期间按该策略继续，条件不成立或失效条件命中就自动交回。合同见 [操作合同](AGENT.md#takeover-packets-and-strategy)。

同一个 `state_id` 只交回一次，且在再次询问模型之前拦截：第二次返回 `repeated_state`。Jev 适配器只发送、校验并记账，不会为了提高置信度缩小选项或重问同一问题。

短计划候选的取舍规则：生存是硬约束（模型不能覆盖），已批准的策略优先于模型排序，其余尊重模型在可行候选中的选择。没有候选能存活时，程序直接说明而不是编一条线。

**实测（新局第 2 层，小啃兽 43HP/意图 12，我 80HP/2 能量、2×打击 2×防御）**：单步 Jev 选「防御」置信度 0.56、1 次请求；短计划候选同样选「防御」候选、1 次请求，并额外给出每候选的独立判断（safe_c0=0.38、safe_c1=0.57）。请求数没有增加。

`plan` 不跨回合，不预测未知抽牌，不把一次HTTP成功或牌移出手牌当作结算完成。每步检查游戏队列、手牌、能量、血量、格挡、状态、敌人意图等；不吻合便停止。实际图像操作不是战斗循环的一部分。

## 下一轮优化的判断标准

1. 未知结果不能自动重复执行，计划偏离不能继续出后续牌。
2. 比较每回合模型往返数、完整回合耗时、主模型接管原因与实战损失。
3. 区分低置信度、真正危险、陌生规则和纯等动画。置信度不是正确率。
   主模型同样可能误算；实际出现过把现有10格挡加防御牌误判为无法挡15的解释。状态包提供程序计算的当前攻击总量和格挡缺口，帮助复核基本算术，但不冒充包含所有回合末效果的完整模拟器。
4. 优先消除“主模型重新确认原计划仍成立”这类无必要接管，而非直接降低置信度阈值。
   低置信度不再自动等于交回主模型：先看程序是否已有确定的斩杀或唯一保命线；没有可靠动作时交回，且同一状态不再重问。
5. 不把胜利后的回顾伪装成行动前已知信息；对照应使用同一局面及相同规则。

当前低置信度阈值、低血量与药水阈值仍是保守试验规则，不是已经优化完成的通用策略。完整局结果及接管统计见 VALIDATION.md，回合级指标见 `scripts/metrics-jsonl.mjs`。
